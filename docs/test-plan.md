
# Test Plan

## Project
E-Commerce Quality Assurance & Test Automation Suite

## System Under Test
SauceDemo Web Application

## Objective
To verify that the major e-commerce workflows of the application behave correctly and to identify functional defects affecting user experience and system reliability.

## Features to be Tested

- Login and authentication
- Product catalogue
- Product details
- Product sorting
- Shopping cart
- Checkout information
- Checkout overview
- Order completion
- Logout

## Testing Types

### Functional Testing
Verify that application features behave according to expected functionality.

### Positive Testing
Verify workflows using valid user actions and valid input.

### Negative Testing
Verify application behaviour using invalid, missing, or unexpected input.

### Smoke Testing
Verify critical application workflows such as login, product access, cart, and checkout.

### Regression Testing
Re-execute important test cases after changes to ensure existing functionality still works.

### Exploratory Testing
Explore the application beyond predefined test cases to identify unexpected behaviour.

## Test Environment

- Application: SauceDemo
- Platform: Web
- Browser: Google Chrome
- Operating System: Windows
- Test Automation Tool: Playwright

## Test Deliverables

- Requirements Analysis
- Test Plan
- Test Scenarios
- Manual Test Cases
- Defect Reports
- Automated Playwright Test Suite
- Test Results

## Entry Criteria

Testing can begin when:
- The test application is accessible.
- Required test credentials are available.
- Major application features are accessible.

## Exit Criteria

Testing will be considered complete when:
- Planned critical test cases have been executed.
- Major defects have been documented.
- Critical workflows have been automated.
- Test results have been recorded.
